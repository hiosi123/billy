# Billy v2 기획안 — "우리 건물 방식대로 설정해서 쓰는 관리앱"

> 2026-11-06 작성. 사장님 지시: "제대로 된 빌딩 관리앱", "커스텀 가능한 관리앱으로".
> 근거: 서버 코드 점검·화면 코드/디자인 점검·국내 서비스/제도 조사(같은 날). 이 문서는 구현 순서의 기준이다 —
> 바뀌면 이 문서부터 고친다.

## 0. 한 줄

검침(배수 계량기 포함) → 고지서 금액 나누기 → 명세서 → 수납까지, **건물마다 다른 관리비 구조를 설정으로** 표현하는
소형 건물(상가·오피스·꼬마빌딩) 관리앱. 조사해 보니 이 흐름을 한 앱에서 끝내는 국내 제품은 없다 — 수납 앱은 금액을
손으로 넣고, 엑셀 상품은 계산만 한다.

## 1. 원칙

1. **지금 결과를 지킨다.** 기존 계산(Go 이식)을 '기존 방식' 프리셋으로 그대로 옮긴다. 운영 2026-08·09 저장값과
   원 단위까지 같은지 `billy_backend/src/billing/legacy-calc.spec.ts`(정답지)가 지킨다. 프리셋 결과가 정답지와
   다르면 배포하지 않는다.
2. **코드가 아니라 설정.** 항목·나누는 방식·반올림·요율·명세서 문구는 건물별 설정. 요율(부가세 10%, 전력산업기반기금
   2.7%(2025-07~), TV수신료 2,500원)은 **적용 시작월**이 붙은 값이다 — 법이 바뀌면 설정만 고친다.
3. **앱에서 보는 금액 = 명세서 금액.** 서버가 계산해 '확정 명세서'(항목별 줄)로 저장하고, 엑셀·이미지는 확정본에서
   만든다. 클라이언트가 보낸 금액을 저장하지 않는다.
4. **실수를 막는다.** 빈칸, 소수점 빠짐, 이상값, 합계 검산(호실 합계 = 고지서 금액)을 저장·계산 전에 확인한다.
5. **내 건물만.** 모든 API 는 그 건물 멤버인지 확인한다(관리자 계정 예외).

## 3. 단계

### 1단계 — 바로(10월 정산 전): 데이터가 틀어지는 구멍 막기 *(작게 배포)*
- 빈칸 저장 막기(지난달 지침이 있는데 이번 달이 비면 저장 안 함), 지침이 지난달보다 작으면 확인
- 달 바꿀 때 불러오기 실패·늦게 온 응답 → 입력 비우고 오류+다시 시도, 저장 막기
- 입력이 바뀌면 계산 결과 지우기
- 수도 이상값 검사(호실 수도 합계 vs 고지서 사용량), 롤오버는 배수 곱하기 전 지침으로
- 검침 카드에 계량기 이름(천리안안과-1/2/3)
- 기반: 정답지 테스트(완료), 부팅 시작 경고 제거

### 2단계 — v2 핵심: 커스텀 관리비 + 확정 명세서
**데이터(추가형 마이그레이션 004~, 부팅 때 자동 적용)**
- `units`(호실=청구 단위: 번호·이름·면적·기본료) — 기존 rooms(계량기 행)를 호수로 묶어 만든다(대표 = MIN(room_id),
  지금 계산이 쓰는 '첫 행'과 같다). rooms.unit_id 추가. → 면적이 행 순서에 흔들리지 않는다.
- `charge_plans`(건물·적용 시작월·프리셋·반올림 방식·items JSONB) — 요금표 버전.
- calc_inputs.inputs JSONB — 항목이 요구하는 월 입력값(고지서 금액 등)을 자유롭게.
- `statements`(확정 명세서: 건물·월·호수·스냅샷 이름·lines JSONB·합계·상태·납부) + `building_settings`(명세서 문구·계좌·납기·연체율).
- `building_members`(건물·사용자·역할) — 권한.

**계산 엔진(`src/billing/engine`) — 항목 방식**
| 방식 | 뜻 | 예 |
|---|---|---|
| `UNIT_PRICE` | 호실 사용량 × (고지서 금액 ÷ 고지서 사용량) | 전기 사용분 |
| `REMAINDER` | 고지서 금액 − 호실 사용분 합계를 면적/사용량/균등으로 | 공용전기 |
| `USAGE_SPLIT` | 금액 × 호실 사용량 ÷ 사용량 합계 | 상수도·하수도 |
| `AREA_SPLIT` | 금액 × 면적 ÷ 총면적 | 일반관리비·승강기 |
| `EQUAL_SPLIT` | 금액 ÷ 호실 수 | 청소비 |
| `FIXED_PER_UNIT` | 호실마다 같은(또는 호실별) 고정액 | TV수신료, 주차비 |
| `PERCENT_OF` | 다른 항목 합 × 요율 | 부가세 10%, 기금 2.7% |
| `UNIT_ATTR` | 호실 고정값 | 화재보험료 |
| `DIRECT` | 그달 호실별 직접 입력 | 수선비 청구 |
- 항목마다: 이름, 묶음(관리비/전기/수도/기타 — 명세서 소계 단위), 법정 14항목 분류, 대상 호실(전체/선택/제외),
  반올림, 화면 표시 여부, 순서.
- 반올림 방식: `end`(반올림 전 값으로 소계를 내고 마지막에 반올림 — 기존 방식) / `item`(항목마다 반올림 후 합).
- 프리셋: **기존 방식(legacy-v1)** = 지금 계산과 원 단위 동일(정답지 테스트). **고지서 기준(kepco-v1)** = 부가세·기금·TV료를
  고지서 금액 그대로 나누고 끝전은 '호실 합계 = 고지서'가 되게 조정. 새 건물은 템플릿에서 시작.
- 검산: 호실 합계 vs 고지서 금액, 사용량 합계 vs 고지서 사용량(1.3배 넘으면 400 — 9월 사고 방지 규칙 유지).

**월 마감 흐름(API)**: 입력 저장 → 미리보기(쓰기 없음, 전월 대비 증감·검산 경고) → 확정(명세서 스냅샷, 잠금, 정정은 다시 확정)
→ 명세서 엑셀/이미지 → (4단계) 입금 체크.

### 3단계 — 새 디자인
- 셸: 폰 = 아래 탭(이번 달 · 정산 · 호실 · 설정), 넓은 화면 = 왼쪽 레일 + 최대 폭. 건물 전환은 상단.
- **이번 달**: 할 일 진행(검침 9/11 → 고지서 → 미리보기 → 확정 → 명세서), 전월 대비 합계, 이상값 알림, '이어서 하기'.
- **정산**: 단계 화면(검침 → 고지서 → 검토 → 확정/명세서), 저장 버튼은 화면 아래 고정, 지난 달은 월 선택.
- **설정 › 관리비 항목**: 항목 목록(순서·숨김), 추가 시 방식을 쉬운 말로 고르고, '지난달에 적용하면' 미리보기.
- 디자인 체계: 한글 글꼴 내장(Noto Sans KR, 상용 2,350자 서브셋 + Roboto 별칭), 글자 크기 단계·간격·모서리 토큰,
  금액은 고정폭 숫자, 공통 부품(금액, 상태 칩, 단계 표시, 오류+다시 시도, 이름 입력 삭제 확인), 큰 글씨 대응.
- 기존 브랜드(네이비 헤더·블루 포인트, 시안 B)는 유지하고 다듬는다.

### 4단계 — 임차인·수납
임차인·계약(보증금·월세·기간·과세 여부), 명세서별 입금 기록(완납·부분·미납), 미납 누계를 다음 명세서로.

### 5단계 — 보내기·보관
앱 없이 보는 명세서 링크, 이미지/PDF 공유(카톡), 법정 14항목 내역 제공. 나중에 알림톡·전자세금계산서.

## 4. 배포 규칙
- main 푸시 = 운영 재배포 → **사장님 확인 뒤에만**. 푸시 전 로컬 임시 DB 로 dist 부팅·응답 확인.
- 마이그레이션은 **추가만**(CREATE IF NOT EXISTS / ADD COLUMN IF NOT EXISTS / 백필은 비어 있을 때만) — 기존 데이터·타입 불변.
- 운영 데이터는 고치지 않는다(세입자 요금). 정정은 사장님이 앱에서.
